# Moka Canvas

A React + LeaferJS visual consistency lab delivered through the same Rust localhost server in browsers and a Tauri desktop WebView.

## Prerequisites

- Node.js 22+ and npm
- Rust stable and Cargo
- Tauri platform requirements for the native target you build
  - macOS: Xcode command-line tools
  - Windows: Microsoft C++ Build Tools, WebView2, and WiX/NSIS as required by Tauri

## Run locally

```sh
make install
make web-serve
```

Open `http://127.0.0.1:8080`. The server provides the built React application, SPA fallback, `/api/health`, and `/api/runtime` from one origin.

For the desktop container:

```sh
make tauri-dev
```

Tauri bundles the built `dist/` directory as a resource, starts the same Axum server on an ephemeral loopback port, and points its WebView to that URL.

## Configuration and data

Application-level state — provider channels, encrypted API keys, defaults and preferences, the recent-project list, and the prompt library — lives in one directory under the platform application-data location, never inside the program tree. Startup rejects a directory that resolves next to the executable, inside the served assets, or inside the working directory.

Three environment variables override the resolved values: `MOKA_METADATA_DIR` (location), `MOKA_METADATA_STORE` (only `file` is accepted), and `MOKA_METADATA_KEY` (the server-mode master key, base64 of 32 bytes). The directory must be on a local disk and must be used by one process at a time; a second process pointing at it fails to start and names the pid holding the lock.

Each project document carries its own canvas schema stamp. A document written by an older schema is migrated forward when it opens — every node's ports are reconciled against the current port table — while a document stamped with a newer schema is refused as an unsupported version instead of being partially read. Documents are never rewritten downwards, so read [docs/release-checklist.md](docs/release-checklist.md) before installing an older build over a newer one.

`GET /api/health` reports the store kind, the redacted root, the schema version, the secret-storage tier, and per-document state. `GET /api/ready` answers 503 until the assets are present, a write probe against the metadata directory succeeds, and any open project directory still exists.

Provider channels, default models, and generation preferences are edited in the settings dialog, opened from the **Settings** button on both the launcher and the editor. A channel carries its base URL, protocol, and a per-capability model list; connectivity tests and provider model listing run from the channel row and the channel editor. API keys are written to the local server once and never sent back: the dialog shows only the masked form, and leaving the key field blank keeps whatever is stored.

`POST /api/v1/generate/{text,image,audio,video}` asks a configured channel for one answer. The endpoint names the capability, so a body that disagrees with it is ignored. An answer arrives as one document carrying the text and any media base64-encoded beside its mime type, kind, and dimensions — nothing is written into a project by these endpoints, so a caller decides what to keep. A text request with `params.stream: true` instead answers `text/event-stream`: repeated `delta` frames, then a closing `done` frame with the whole answer. A stream has already sent its status line by the time it can fail, so a failure travels inside that closing frame rather than as a status. Video is the exception — it starts as a handle and is polled at `GET /api/v1/generate/tasks/{id}` until it ends, and a handle the server never issued is missing rather than merely unfinished. Every failure answers the same problem document with the same code in the body and in an `x-error-code` header, and a caller never receives a provider's raw response body — only its message, with any credential that message echoed replaced by the masked form.

A node carrying a generation spec runs on the provider rather than on a local operator, so a run started at `POST /api/v1/projects/current/runs` is what asks a provider on a canvas's behalf. Its answer is filed in the project as an asset bearing the run it came from, the node that asked, the inputs that travelled, and the parameters it was asked with — never the credential those parameters resolved to. An ask answered several times over keeps its first answer on the node that asked and gives the rest a card each. A node that already says or shows something keeps it, and the answer goes on a card beside it joined back to what it came from, so asking again is how a canvas is compared rather than overwritten — and asking once more writes into the card that is there instead of adding a second. An ask that fails leaves the node saying what it said before. A deployment configured without the provider executor refuses such a node before the run starts, and the editor disables the button and says why rather than offering one that cannot work.

Across the top of the editor sit the project's name, its canvas tabs, where the last save has got to, and what acts on the document as a whole: **Undo** and **Redo**; **Add node**, opening the same quick-add menu a double-click on blank canvas gives and landing the chosen node at the middle of the view; **Group** and **Ungroup** over the selection, offered only when they would do something; **▶ Run** over every selected node a run can carry; **Import…**, filing files from this machine as assets and landing them as nodes where the view is pointing; and the settings and export dialogs. The strip under the canvas keeps the tools, the zoom, and the panel toggles.

Asking is done in the editor rather than at the API. Selecting a text, image, audio, or video node brings a panel up under it; the same panel is reached through **Generate…** on the node's menu, and through `Enter` on a node a provider can answer, where `Enter` on a text node that already has words edits them instead. The **Prompt** toggle in the editor's footer turns the panel-on-selection off, and `Escape` closes it for as long as that node stays selected. The panel holds the mode, the model, the prompt, and the parameters that capability has, each of which says what the global default is on the choice that leaves it out; what is typed is written to the document when focus leaves the field, so a keystroke is neither an undo entry nor a save, while a control that is clicked writes straight through. Choosing a shape gives a node that is still empty that shape. A node that cannot be asked yet says why on the button — nothing typed and nothing connected to, no model of that kind configured, a prompt past its limit, or a deployment with nothing that can reach a provider — and a prompt near its limit is counted out loud beside it. The button becomes **Stop** while a run is going and **Ask again** after one that gave up, which follows that run rather than starting one with nothing to do with it.

What an ask is given is chosen rather than assumed, and the choice sits on the panel above the prompt. **Wired in** takes whatever is connected to the node, in the order the wires were drawn, and opens a group into its members; **By hand** takes only the nodes listed there, in the order they are listed, which is the order they count for; **In the prompt** takes only what the prompt points at with `@`. Typing `@` offers the nodes this one could mean — upstream of it, listed by it, or any other on the canvas holding something — a picture by its thumbnail and a text by its first words, and what is chosen is written into the document as `@[node:<id>]` and shown as a chip under the field that can be looked at, taken out whole, or followed back to the card it names. A chip naming a node that is gone says so, and the button refuses with it rather than sending an ask that quietly means something else. An asset dragged from the resource panel onto the bar is wired in beside the node or added to its list, whichever mode is in force; the bar is not a place to leave one where the prompt decides, since nothing dropped there would be read. A wired-in reference can be moved to the input it belongs on, found on the canvas, or disconnected, a listed one can be dragged into a different place in the list, and each of those is one step of history rather than several.

**Preview** asks `POST /api/v1/projects/current/generate/preview` what the node will send, rather than working it out a second time in the browser: the words exactly as a run sends them, with upstream text folded in under a `[Text 1]` heading of its own, and every reference with its mime type, dimensions, length, size, and the card it came from. One resolver answers both the preview and the run, so the two cannot drift apart — a panel showing three references while a request carries two is the kind of wrong nobody can find from the answer. Anything that will not travel is said outright instead of being left out quietly: a mention naming a node the canvas has never heard of, a file that is not there any more, text cut by so many characters to fit the limit. A node can also be filled without asking for anything at all. **Image from these words** on a text node's menu — with video, audio, and a rewrite beside it — makes a node to the right of the words, wires them into it, and opens its panel with nothing asked for yet, so a choice from a menu cannot spend anything on a provider; and an empty asset node offers what the project already holds, which puts a picture into a node that was waiting without asking for one.

The card carries the state of the run it was asked in: how far that run has got, or a band that says only that it is going where nothing has measured one; a mark with the reason where an ask failed, which leaves what the card held before in place; and how many answers one ask brought back. The inspector lists every ask a node has had rather than only the newest, and every result it holds, with the one the node shows named as such; making another of them the one shown is offered there and on the menu of both the node holding a batch and a card holding one of its answers, and is written into the document like any other edit. Closing a project or switching canvas with a run still going says how many are going and stops none of them: a run belongs to the project, so what it makes is written into it whether or not anybody is still looking at the canvas it was asked from.

Two or more nodes selected brings a bar up over them for what can be done to them together: **Group**; lining them up on the left, the middle, the right, the top, the middle row, or the bottom of the room they take up together; giving them all the widest one's width or the tallest one's height; spreading them out with the same room between neighbours along either axis; and **Delete**. Each is one step of history, an act that would change nothing writes nothing, and what is arranged is the members rather than a group's frame, which stands for them and is left where it is.

Not everything on a canvas is asked of somebody. Selecting one picture brings a row of tools up over its card — **Crop**, **Split**, **Resample**, **Tilt**, **Repaint**, **Describe** — and which of them it offers is the reader's to choose under **Settings** → **Preferences**, kept on this machine rather than in the document, so a bar somebody has tidied stays tidied and travels in no package. The first four are arithmetic on pixels that are already here, so they cost nothing, give the same answer twice, and work in a project with no channel configured; `POST /api/v1/projects/current/tools` does them, told the tool, the picture, and the parameters, and nothing else. Each asks its own question first — a proportion, or a region given in the picture's own pixels rather than in the rectangle a card happens to be drawn in; a grid; a size by name or one asked for, and how a picture is to meet a box that is not its shape; an angle to turn and tip by — and refuses what it cannot do before anything is written, whether that is a region outside the picture, a division past its ceiling, or a proportion nobody can read. None of them rewrites the file a card holds. What they make is filed as an asset of its own, named after the picture it came from and carrying the tool, the parameters and the subject as its provenance with no run behind it, because nothing ran; it lands on a card to the right, wired back to what it was made from, so the step reads in the graph as one picture made out of another rather than as a file that changed underneath a node. Every piece of a division arrives in one step of history and all of them are selected, so a sheet cut nine ways can be grouped the moment it lands, and letting go of that step takes the cards and the wires while leaving every file filed. A picture whose file is missing, has changed on disk, or is empty gets the reason on the bar instead of a tool that would fail in a moment reading as the tool breaking, and the inspector says which tool made the picture it is showing and which picture it was made from — offering a run only where one started.

**Repaint** and **Describe** sit in the same row and are hidden by the same setting, but each is an ask rather than arithmetic and costs what an ask costs. Repaint takes a region painted over the picture itself, because a region worth repainting is a shape somebody can see and not one they can give in four integers; what it makes is the two halves of an ask rather than a repainted picture — the marking filed as a mask of its own and wired into the picture's mask port, the words written into that picture's ask — so the repaint is one press from being run and nothing has been spent from the dialog. Describe asks a model that can see to read the picture back as the words that would make it, shows the answer as it arrives so that a model answering about nothing is caught there rather than after a second generation spent on its guess, and files what it said as a text node wired into the picture's prompt, which makes the picture askable again from the words it was read back as.

The column beside the canvas is the project's material shelf. Every file carries what a reader said about it — the words it is filed under, a note, and a keeper mark that keeps it to hand — and where it came from: brought in, made here by a run, or saved from a node's own work, which the shelf works out from the record a run left rather than from a field free to disagree with it. The shelf narrows by a word matched against the name, the words, the note, and the summary; by shelf; by origin; by keepers; and by every word chosen at once, with the words counted over the whole shelf so that choosing a second one narrows the list instead of emptying it. A node holding a picture, sound, or video is marked as one to hand on the shelf, with the ask it was given as its summary where it had none; a text node's words are written to the shelf as a file of their own, read on the server from the document rather than retyped from the card, and filing the same node again gives back the file that was already made for it rather than a second copy. **From assets…** takes the shelf the other way, from the quick-add menu, from a node's reference bar, and from beside the assistant's about line: one dialog with the same search, shelf, and word controls, in which several files may be chosen at once, saying before anything is taken whether what is chosen will be inserted as so many nodes — one undo, all of them selected — or added to the node that asked, wired in beside it or listed by it according to the mode in force.

Asking can be carried on in words rather than one node at a time, which is what the **Assistant** tab beside the inspector is for. A conversation is about cards: the selection, and whatever feeds those cards, is what a question is asked of, and the head of the panel says so in counts rather than leaving it to be inferred. **Ask** and **Rewrite** send that to a model that writes — Rewrite taking only the text card chosen, so a rewrite cannot wander off into the rest of the canvas — while **Image**, **Video**, and **Audio** go through the same run pipeline a node panel uses, so what comes back is a card on the canvas and an asset in the project rather than something to copy out of a chat window. A card asked about that way feeds the ask over a wire rather than as words quoted into it, which is why the picture that lands is joined to the text it was made from. Nothing is spent until Send is pressed, and a kind with no model configured says which kind is missing and offers the settings rather than answering the ask badly.

What an answer said stays on the canvas. Each kept line can be put on the canvas as a card of its own, written over the text card it was a rewrite of, copied, downloaded, followed back to the card it made or the shelf its file went onto, and a card that came back empty can be asked again from the line that says so without a second card appearing for it. A turn that failed is a line in the conversation rather than a notice that fades: a reader coming back later can see that this was asked and nothing came, and can ask again from that line. A conversation keeps only as much of itself as the window holds, stepping back by increments rather than rendering hundreds of lines at once, and a card a line was about that has since been deleted keeps its snapshot with the line saying plainly that the card is gone. How many conversations a canvas has had, what each is titled, and what each holds is document state, so it is one canvas's record rather than this machine's; for a words ask, the last few lines can travel with the question, and the panel counts out the characters that go so that what is offered is what will be sent.

A project travels as one `.mokapkg.zip`, written by `POST /api/v1/projects/current/export` and read back by the launcher's **Import package**. **Export** asks two questions first and both start off: whether the record of the runs this machine made goes along, and whether assets no node points at are left out. Answering neither gives the package of the work — the document, its assets, and a manifest naming every rule that skipped a file with the count and the room it freed — with the run that made each generated asset, and the conversations had over each canvas, taken off it, so what arrives somewhere else says how a thing was asked for without saying which machine answered or what was said to it there. Ticking the first gives a backup for moving one's own work to another computer, which keeps those records and those conversations and says in its manifest that it did; ticking the second trades the material shelf for size, and the question counts what would be left behind before the choice is made rather than after. Model channels, API keys, the prompt library, the recent-project list, and the logs are application state rather than project state, so neither kind can carry them — the dialog says so instead of leaving it to be discovered. An export stops and names the assets it cannot find rather than writing a package that opens broken, and offers to go ahead with the gap flagged in the manifest and in the toast that reports it. `includePersonalHistory` and `onlyReferencedAssets` are the two request fields, and a body carrying neither asks for the package of the work. Importing takes a package made by this build or the one before it and refuses a later one with the range it does read; a package that does not say it carried the run records is cleaned to what this build keeps on the way in, so a file that has been round an older build does not bring that build's history with it.

See [docs/security.md](docs/security.md) for how credentials are protected and what that protection does not cover, and [docs/deployment.md](docs/deployment.md) for running the standalone server.

## Quality and packaging

```sh
make check
make test
make package-web
make package-macos
make package-windows
make cross-package-windows
make clean
```

`make check` is the full baseline gate: formatting, lint, typecheck, the production web build, the frontend Vitest suite, Rustfmt, Clippy with warnings denied, and the backend `cargo test` suite. `make test` runs just the two test suites (Vitest and `cargo test`) without the lint/format/build gates. `npm run test:e2e` drives the built application in a real browser through Playwright: the launcher-to-editor critical path, missing-asset recovery, a provider-settings round trip, a generation driven end to end against a stand-in provider the suite brings up itself, a conversation asked for a picture that lands on the canvas and is filed as an asset, and a picture cropped from the row of tools over its card — each against a server started with a temporary metadata directory and a master key generated for that boot, since server mode will not invent one and a channel can hold no credential without it.

`package-web` stages the built site and a native `moka-server` binary under `release/`. Native app packaging is intentionally host-native: build macOS artifacts on macOS and Windows installers on Windows. Release signing and macOS notarization require organization-specific credentials and are not part of this baseline.

`cross-package-windows` cross-compiles the Windows NSIS installer (`-setup.exe`) on macOS using the `x86_64-pc-windows-gnu` Rust target. It requires the mingw-w64 toolchain and NSIS (`brew install mingw-w64 makensis`); the Rust target itself is installed automatically if missing. The build sets `LC_ALL=en_US.UTF-8` because makensis crashes with `std::bad_alloc` when a non-UTF-8 locale is active (see NSIS bug 1165). `make clean` removes `dist/`, `release/`, `src-tauri/target/`, and TypeScript build caches.

## Comparison workflow

1. Compare **Component lab** and **Token parity** in a browser and Tauri at the same window size.
2. Resize each runtime and use **Interaction lab** controls to ensure stage destruction/recreation is clean.
3. Test high-DPI scaling and direct navigation to `/showcase`, `/playground`, and `/tokens`.
4. Verify no remote fonts, images, CDN scripts, or Tauri JavaScript APIs are required by the frontend.
